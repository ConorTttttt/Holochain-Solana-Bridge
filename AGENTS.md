# Parallel coding agents — Solana ↔ Holochain bridge

This repository is **research/development ONLY**. There is no production bridge. Never use real funds, deploy to mainnet, or represent refundable deposits as collateral for transferable Holochain credit.

## Immutable project rules

1. **No Holochain value issuance:** preserve `holochain/evidence-gate.mjs` denial, including `creditEligible: false`. Only the project maintainer may authorize changes after explicit security-gate review.
2. **No redemption service or mainnet deploy by default.** Use disposable classic SPL tokens and localnet. Devnet/testnet proposals remain behind gated PRs.
3. Do not add secrets, RPC API keys, mnemonic seeds, keypair JSON or production wallet material to Git. Never log them.
4. Never claim `anchor build`, local-validator tests, source equivalence, independent audits or integration tests passed unless the commands were actually run; attach logs and versions.
5. A verified Solana RPC snapshot is not a proof of economic finality to Holochain. Holochain RAVE output alone does not prove settled Solana collateral.
6. Every issue gets a dedicated feature branch `agent/<lane>/<issue>-<slug>` and a PR. No agent pushes to `main` or force-pushes others' branches.
7. Treat source-chain finality, account ownership/PDA derivation, idempotency, replay prevention, U64 exact arithmetic, and upgrade/admin controls as security-critical.
8. Do not silently widen token support to SOL, Token-2022, permissioned mints, arbitrary SPL assets, or change the signature trust model.
9. Code generated by an agent receives human review; independent security review is needed for economic state changes.

## Parallel lanes — only one primary author per file

| **SEC** (security reviewer) | Threat model, adversarial tests, invariants, PR review, release-gate decisions. | `security/**`, `docs/SECURITY_GATES.md` | Independently review SOL/OBS/RAVE; **cannot self-approve** economic changes |
| **CI** (build/integration engineer) | Reproducible CI, localnet test harness, lint/test matrix, isolated E2E dry-run. | `.github/**`, `scripts/**`, `tests/integration/**` | Run actual tools; aggregate evidence but do not alter verification semantics |

If a change crosses ownership boundaries, open two coordinated PRs and document a stable API/IDL contract first. Avoid simultaneous edits to `README.md` or this file.

## Work protocol

- Start from an assigned GitHub issue. Read `docs/SPRINTS.md` and its dependencies; identify the gate before coding.
- In the PR include **what changed, exact commands + outputs, security impact, affected trust boundaries, handoff to other lanes, and unresolved questions**.
- Add tests for both expected behaviour and an adversarial case.
- For critical files, SEC review is mandatory. All tests must run on CI; a CI workflow that skips Anchor compilation is not evidence it compiled.
- Never remove or work around security interlocks to satisfy a demo.
- Make progress in a branch/PR; an issue or agent prompt does **not** launch or schedule an autonomous process.
