## Interface / evidence contract

- `verifyDepositCandidates({rpcTransaction,signature,expected,genesisHash,idl,finalizedClaim:true,blockhash,source})` returns zero or more frozen `solana-deposit-transaction-candidate-v1` objects. Requires a **trusted, pinned** manifest (`expected.program`, `mint`, `config`, `vault`, `scope`), actual generated Anchor IDL with matching ID, explicit numeric transaction version `legacy|0|1`, decoded binary bytes, matching first signature, locally valid **all required Ed25519 signatures**, success `meta.err === null`, depositor signer, canonical PDAs, exact deposit discriminator/amount/recipient, one `TransferChecked` CPI and exact aggregate pre/post SPL balances. Unknown transaction versions, unresolved ALTs and unrelated SPL movements touching vault/source cause failure, not empty results.
- Each candidate includes `id = genesisHash + ':' + program + ':' + receiptAddress`; `occurrenceId = genesisHash + ':' + program + ':' + signature + ':outer:' + index`; `signature`, `transactionVersion`, `finalizedSlot`, `blockhash`, SHA256(`wireTransaction`) `transactionHash`, `instructionPath`, `cpiPath`, `program`, `configAddress`, `vaultAddress`, `mint`, `receiptAddress`, `sourceTokenAccount`, `depositor`, `recipientCore` (hex32), `holochainScope` (hex32), decimal-u64 `depositNonce` and `amountBaseUnits`, `configBump`, `receiptBump`, `evidenceTrust`, `transactionVerified:true` meaning **locally checked against RPC-reported bytes only**, `verifiedByRpcClaim:true`, `independentConsensusVerified:false`, and **`creditEligible:false`**.
- `attachReceiptObservation(candidate, observation)` requires a canonical existing `solana-receipt-observation-v1` with same all identities, scope and economic values, matching bumps, and finalized observation slot >= claimed deposit slot; returns `solana-deposit-evidence-v1` with nested `receiptSnapshot` (raw account digests, refunded state), `observationSlot`, `refundedAtObservation`, explicit `limitations[]`, and `creditEligible:false`. A *later* account observation is NOT equivalent to historical post-state; a now-refunded receipt is still matched to an earlier deposit but never becomes collateral.

### Durable indexer contract

`indexFinalizedRange({rpcUrls:[url1,url2],expected:{program,mint,config,vault,scope,idlSha256},genesisHash,trustedDeploymentSlot,idlText,ledgerPath,toSlot,fetchFn})` requires a trusted deployment slot, exact generated IDL **byte hash**, two distinct providers, matching genesis, sufficient finalized height and unpruned historical access. Iterates `getBlocks` produced-slot enumerations and complete raw `getBlock` responses with `commitment:finalized`, `transactionDetails:full`, `encoding:base64`, **numeric `maxSupportedTransactionVersion:1`**. A returned `null` for an enumerated block is an error. Provider mismatch is an error rather than selecting a majority.

On an accepted candidate, query the receipt/config/vault/mint as a four-account finalized snapshot from both providers, reconcile, then atomically commit the entire resulting **receipt evidence + blockhash + checkpoint** using `DepositLedger`. An exclusive process lock prevents concurrent writers, and restart resumes at checkpoint+1. Receipt identity and creating `signature:instruction` occurrence form separate uniqueness checks. Same evidence replay is idempotent; conflicting receipt or block identity halts. `getBlocks` lists produced slots (skipped slots are implicit): two matching providers **do not** cryptographically guarantee enumeration completeness. Operator must maintain an archive/independent gap monitor and compare to authoritative finalized history before any acceptance claim. Unexpected process termination leaves a stale `.lock`: operator recovery after validating ledger integrity is intentional, **not** automatic lock stealing.

### Explicit limitations / fail-closed omissions

1. **RPC finality is not an independently verified consensus certificate.** Two RPCs can be corrupted or share upstream data. Signature cryptography is local, but signed bytes and claims of inclusion are still reported by RPC.
2. **Refundable custody is economically ineligible.** The SOL prototype has a successful `refund` instruction; OBS initial transaction scanner deliberately halts on a successful refund rather than silently treating an earlier deposit as still backed. A separate tested refund transition/lifecycle journal is required for continuing finalized scanning through refunds.
3. The scanner currently accepts only **top-level** deposit instructions with one directly attributable SPL CPI transfer and transaction-wide unambiguous source/vault deltas. Ambiguous nested CPI deposits, mixed custody transfers, missing token balance metadata, unsupported versions or missing historical data halt rather than downgrade.
4. The slot cursor and evidence share one atomic rename+fsync durability boundary on one local filesystem. Distributed multi-worker indexing, archive completeness against an independent validator, disaster-recovery snapshot signing, upgrade governance, bytecode/source equivalence after redeployment, and true Holochain fork safety are **not implemented**.
5. The generated IDL schema validator must run on the compiled artifact in CI; a synthetic test IDL never proves deployed source equivalence. `@solana/kit@8.6.0` is pinned but the **reviewed Observer package lockfile is still missing**; no `npm ci` of the new branch is claimed. The requested signed transaction fixture is pending SOL. Maintain this PR as draft.
