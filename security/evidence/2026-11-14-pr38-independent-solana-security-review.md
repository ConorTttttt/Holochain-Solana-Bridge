## Changes required (test/evidence-layer; no mainnet authorization)

**SEC-38-1 / HIGH — Witness identity and signer claims not bound to signed bytes.** `tests/solana/verify-witness-bundle.mjs:43-85,135-168` verifies Ed25519 against message static signer keys and signature #0, but never compares decoded signer addresses with archive `feePayer`, `signerPubkeys`, `instructionProgramId`, `instructionAccounts`, `instructions[].programId/dataBase64`, or `recentBlockhash`. A modified archive can relabel those unauthenticated fields while keeping all original signatures, blocks and bytes untouched and still satisfy the checks implemented in this verifier. Add fail-closed assertions for fee payer (static key 0), required signer set/order, compiled instructions and program indices, account addresses/flags and recent blockhash against both recorded metadata and JSON RPC. Add a tamper regression changing only feePayer/signer/program/instruction labels; require an attributed rejection. All **54 actual** witnesses were independently consistent; the flaw is missing enforcement in the verifier.

**SEC-38-2 / MEDIUM — Wire-byte requirement is optional.** `verify-witness-bundle.mjs:145-151` checks submitted bytes only `if (typeof record.signedWireBase64 === 'string')`. Although every observed signature has a wire-bearing record, deletion of all such fields is not rejected. Require at least one exact submitted wire record per finalized signature (and reject malformed/contradictory duplicate records), then add a deletion tamper case.

**SEC-38-3 / MEDIUM — Tamper harness does not pin rejection reasons.** `tests/solana/verify-witness-tamper.mjs:107-115` asserts only nonzero exit. This permits future unrelated failure (e.g. wrong setup, parse exception or missing ELF) to masquerade as a property-specific rejection. The inspected 2026-11-14 run happens to show the intended failures; add a named expected failure identifier/regex per case and assert it; negative control must accept. Test v0 and at least two signers in an independent fixture too (no such transactions in this artifact).

**SEC-38-4 / provenance and trust limitations.** `verify-witness-bundle.mjs:15-27` treats a self-reported, only regex-validated genesis hash as network identity; it does not authenticate an RPC ledger or bind actual source-tree state to the commit. `localnet-build.sh:29-35` executes `anchor keys sync` **after** checkout, which edits tracked local program ID declaration/config; `source-commit.txt` therefore identifies the initial checkout but not necessarily exact post-sync compiled source bytes. Archive deployment was read at `confirmed` (`integration.test.mjs:34-44`) without historical slot-authenticated ProgramData. `sol-verify-temporary.yml:41-47` executes a remote Solana installer and installs `anchor-cli` from `otter-sec/anchor` **tag** v1.2.2 rather than an independently approved immutable commit. Root `Cargo.lock` is absent at reviewed ref; workflow `cargo check` lacks `--locked`. The tests' `tests/solana/package-lock.json` exists and is used with `npm ci`. Record generated source patch/toolchain provenance, pin canonical/fork Anchor commit and supply-chain digests, commit/review Rust lock graph, and keep network confidence explicitly local/RPC-derived.
