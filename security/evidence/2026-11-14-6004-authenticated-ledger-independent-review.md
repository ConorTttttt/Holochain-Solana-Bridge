## 4. Authenticated-ledger threat boundary (confirmed)
Reviewed combined `observer/src/ledger.mjs`: single-writer `.lock` with explicit stale-lock intervention, atomic temporary-write + file and directory fsync, JSON state, stored SHA-256(`JSON.stringify(evidence)`) fingerprint, `processed` dedupe and `blocks`/checkpoint checks. This is useful **local crash consistency / accidental-corruption detection**, not authenticated history. Existing SEC test `security/test/ledger-corruption-boundary.test.mjs` was previously run byte-identically alongside the actual OBS ledger (independent SEC evidence report records 29/29 for a combined reference suite); **no fresh GitHub Actions integration of this new SEC test has been verified**.

**Demonstrated local-write attacks:** (a) modifying evidence alone is rejected; (b) modifying stored `blocks['10']` and increasing checkpoint to 20 is accepted at recovery, permitting skipped scans; (c) changing an amount and recomputing the adjacent unkeyed SHA fingerprint is accepted. A full-filesystem adversary can also truncate/rewrite or restore an older valid snapshot, alter both journal and checkpoint, seize lock state, and hide replay between independent stores. Checksums/hash chains *without an independently trusted latest digest* do not stop rollback, advancement or malicious rewrite; an HMAC stored with its secret on the same compromised host does not fix full-host compromise.

**Agent 3 threat-aware design + tests:** persist append-only signed or witnessed events and periodically anchor their *monotonic latest root/checkpoint* to an **independent** append-only, access-separated trust domain; bind genesis, program, deployment epoch, canonical tx/occurrence identity and source attestations; use off-host verification/attestor quorum or externally immutable logs, not single-host HMAC as a claimed sovereign proof. Test tampered entry/recomputed checksum, advance, rollback to old valid snapshot, deletion/truncation/reorder, two independent ledgers accepting duplicate, crash at write/fsync/rename, stale lock/operator recovery, key compromise/revocation and external restoration. On unrecoverable trust divergence, fail closed and rebuild by replay from a trusted independent canonical Solana source; require reconciliation before any economic action. Independent witness/key compromise still needs specified recovery governance.

## 5. Unyt actual validation and numeric/collateral invariants

Unyt Sandbox v0.117.0 release bytes, expected SHA-256s and publisher-key minisign were verified in PR #34's release job. The compatible Holonix bundle-inspection failure remains separate. Current shadow validators are JavaScript/model logic; no deployed integrity-zome enforcement of replay/fork/recovery/standing has been authenticated. `Parked` is not globally final under partitions, and `InitProperties` are local installation data, not DHT validation inputs. Countersigning is feature gated and must be verified in both HDK and the actual conductor. Agent 4 must produce two-conductor negative evidence for duplicate commitments, fork/partition Parked standing, recovery/restore, migration and cross-DNA/agreement replay, using authenticated zome hashes, functions and capabilities.

Use only **canonical unsigned u64 decimal strings/BigInt** for Solana base units. A six-decimal 2^53+1 base-unit input `9007199254740993` is exactly `9007199254.740993` whole RAVE units. The ZFuel signed-i64 6-decimal micro-unit ceiling is **9223372036854775807**, below Solana u64 max **18446744073709551615**. For mint decimals d<=6, scale exactly by 10^(6-d) with checked positive-i64 overflow; for d>6, require exact divisibility by 10^(d-6) or reject, never round. Reject unsafe numeric JS values, leading-zero or signed ambiguity, duplicate raw JSON keys before `JSON.parse`/`serde_json::Value`, unsupported MessagePack shape and Rhai cast loss. Agent 4 owns executable *actual ingress* checks; the SEC JS model is reference evidence, not zome validation.

Collateral acceptance is **not** just `vault >= total_active`: require **exclusive, unrefundable available collateral** >= **all** outstanding spendable credits + pending withdrawals + unsettled redemption/fees/other liabilities (in one exact unit and with explicit asset matching), with no simultaneous double count of already-reserved amounts. An irrevocable burn/lock/settlement protocol, replay fences and reserve accounting across both chains must be independently witnessed. Current refundable prototype **fails this economic invariant by design**.
